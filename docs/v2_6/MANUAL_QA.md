# V2.6 手動QA

Simulator用の **AI Life Planner V2.6 QA** は localhost:56621 に接続する。V2.6専用のテストアカウントでログインする。AI未設定の状態では最初の2項目とTask管理を確認できる。AIを設定する検証は、外部送信と使用料を了承したうえで分離環境で行う。

| 操作                                                                             | 期待結果                                                                                                                                               |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 端末のカレンダー権限を拒否して「今日」「タスク」を開く                           | 予定を確認できない旨が出る。推薦、追加、完了、取り消しが使える。                                                                                       |
| 講義13–15時、アルバイト18–21時を端末に入れ、「今日」で15分と60分を切り替える     | 直近の予定と次の予定までの参考時間が見える。時間内に収まりそうな項目が優先され、緊急Taskも残る。重複・取消・終日の予定も試す。                         |
| 「予定」から「この日の予定をAIに相談」。参照情報の「なし」のまま送信する         | 日付は引き継がれ、端末予定の詳細は同封されない。通常の会話が履歴に残る。                                                                               |
| 参照情報で「予定の有無」を選び取得する                                           | 選択日の予定の有無を確認できる。タイトルと場所は送らない。                                                                                             |
| 「選んだ予定の詳細」で講義だけ選び、場所は共有しない。送信後、同じ会話で再度送る | プレビューに講義のタイトル・日時が出る。最初の回答は一時表示で履歴に残らず、次回の共有設定は「なし」に戻る。場所を選ぶと場所もプレビューに表示される。 |
| 共有なしで「今週はレポート優先」と相談し、期間を確認して個別承認する             | 承認前は推薦が変わらない。承認後、今日に適用中の方針と理由が出る。解除と再適用ができ、期限後は影響しない。                                             |
| タスク詳細からAIに相談し期限を変える。個別編集・選択承認する                     | 変更前後が表示され、承認した変更だけが反映される。編集直後には取り消せ、別の編集後は競合として案内される。                                             |
| タスクの分割案を却下し、別の分割案から1件だけ選んで承認する                      | 却下案は反映されず、選んだ小さな行動だけ追加される。短時間の二重操作で増殖しない。                                                                     |
| AI未設定・予算上限・通信失敗時、再起動後、VoiceOverと大きな文字で試す            | Task管理が続けられ、期間と解除状態を再取得できる。共有の場所設定・対象予定を読み上げで判断できる。                                                     |

試用で動作と送信プレビューを確認し、公開先の互換性と移行順（DB、Edge Function、Nativeアプリ）を決めた後、ユーザーが作業ブランチをpushしてPRを作成する。

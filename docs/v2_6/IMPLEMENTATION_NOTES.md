# V2.6 実装とQA環境

- Todayは DayAgenda から受け取った端末予定と、認証済みリポジトリから取得した有効期間内の方針を、既存 recommend 関数に渡す。予定や方針の取得失敗はTask取得から独立して扱う。
- AI Edge Functionは v2-chat の認証、構造化出力、月500,000マイクロドルの予約と確定を再利用する。共有データは1日・最大12件、入力上限付き。場所の同意がない入力の場所と、ID・参加者・メモ等はサーバーで除外する。
- マイグレーション 20261118130000_v26_ai_calendar は方針、編集取り消し用の変更前値、却下時刻を追加する。方針はRLSで所有者だけが読み、書き込みはRPCに限定する。承認は一括トランザクション、下書き単位で冪等。編集は明示された列だけを更新し、承認後に別の編集があれば取り消しを拒否する。新規Taskの取り消しは通常のTask詳細から削除確認を使う。
- 既存の会話・Goal提案・計画提案の履歴は保持する。Goalと計画の新規AI提案は生成しない。承認RPCは旧Goal提案の適用を拒否するため、V2当時のGoal承認を前提とするSQLは旧スキーマで確認する。
- 分離QAは localhost:56621（Postgres 56622）。従来の55321・56421とは別のスタックとアプリID。QAの巻き戻しは旧ビルドを従来のQAに接続して確認する。V2.6 QAはその作業ディレクトリで supabase stop を実行し、データを保持したまま停止できる。既存の共有DBを巻き戻す場合は、スナップショットを別環境に復元してから接続先を切り替える。

# 時間入力UI（Step 7）

Settingsの活動開始・終了、最小空き時間、Calendar共通余白、およびCalendarの個別余白は
現在値を表示する設定行から編集する。選択パネルの「決定」でフォームへ反映し、既存の保存ボタンで保存する。
キャンセル・外側タップでは変更を破棄する。保存中は編集・重複保存を無効にする。

## プラットフォームと操作

- Native: 下から開くモーダル内で時・分を独立してスクロール選択する。Safe Areaと縦スクロールに対応する。
- PC Web（幅768px以上）: 設定行付近のポップオーバー。時・分は標準selectで選び、矢印キーも使える。
- スマホWeb: 画面下部のシート。内容が収まらない場合はスクロールする。
- WebはTab / Shift+Tabでパネル内を移動し、Escapeでキャンセル、閉じると起点へフォーカスを戻す。
- 活動終了の当日／翌日は終了時刻パネル内で選ぶ。活動時間もフォームに表示する。

Expo / React Native標準のModal、ScrollViewと既存テーマを利用し、新しい依存ライブラリは追加しない。
Webの標準selectはキーボード操作と保守性を優先している。Nativeは標準ホイールではなく、選択状態を示すスクロール一覧。

## 値の互換性

時刻の通常候補は00 / 15 / 30 / 45分。「1分単位で選ぶ」で00〜59分を選べる。
既存の08:10・23:59などは正確に表示・保持し、開閉・再保存だけで丸めない。
時だけ変更しても元の分を保持する。

最小空き時間は10 / 15 / 20 / 30 / 60分、余白は0 / 10 / 15 / 30 / 60分を候補とする。
「その他」で整数分を入力でき、非プリセットの既存値も保持する。
最小空き時間は既存のDB integer範囲の正の整数、余白は0〜240分。負数・小数・不正文字は拒否する。
個別余白の0分上書き、共通設定への復帰、予定発生回の保存単位は維持する。

Repository・DB schema・計画日・Planning Window・DST判定は変更しない。
活動期間0分超〜24時間、timezoneの検証は既存のSettings保存処理で実施する。
DB migration・Web公開・実機への上書きインストールはこの変更には含まない。

## 確認手順

1. Settingsで開始・終了を開き、時・分、当日／翌日を選択。キャンセルで元の値、決定でフォームの値が変わることを確認。
2. 09:00〜翌日02:00が17時間と表示され、保存・再読み込み後も保持されることを確認。
3. 23:59・08:10、最小7分、余白17分などを保存・再読み込みし、値が丸められないことを確認。
4. 余白の0 / 240分と不正値、Calendar個別余白の保存・解除、保存エラーを確認。
5. Webは幅375 / 390 / 768 / 1440px、マウス・キーボード、Escape・外側タップ・フォーカス復帰を確認。
6. iPhone実機では小さい画面・文字拡大・VoiceOver・Safe Area、詳細入力時のキーボードと決定操作を確認。

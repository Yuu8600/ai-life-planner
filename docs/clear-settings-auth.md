# Settings・Auth Clear UI（Step 9C-3）

## Settings

ClearのCard・SettingRow・既存の時間選択部品を使い、活動時間、空き時間・予定の余白、
地域・時間帯、既存の連携案内、アカウントの順に整理した。本文の最大幅は720px。
時刻・終了日・余白の選択方式、1分単位の既存値、バリデーションとRepository契約は維持する。

保存エリアを本文のスクロール外に配置し、Safe Area・iOSのKeyboardAvoidingViewに対応した。
保存中は入力・保存・閉じるを無効化する。選択だけでは保存せず、既存Planを自動変更しない。
保存後はRepositoryが返した設定を反映するが、画面全体やAccountを再マウントしない。

保存エラーの全文は本文末尾のNoticeへ表示して自動スクロールし、固定エリアには短い状態と
保存ボタンを残す。文字拡大時に通知が入力領域を占有しないための構成である。
保存時にはキーボードを閉じ、Webでは保存結果エリアへフォーカスを移す。
入力エラーは各項目と保存エリアの要約で伝える。

「閉じる」は未保存の変更がある場合に破棄確認を行う。ブラウザの戻る、OSのジェスチャー、
ログアウトは今回の確認対象に含めず、既存のナビゲーション・認証動作を維持する。

## Auth・Account

Authはアプリ名・短い説明、モード切替、メール・パスワード、実行ボタン、状態通知の順に
整理し、最大幅480pxのCardにまとめた。メールのReturnでパスワードへ移動できる。
Webのモード切替はTab・矢印・Home/Endに対応する。切替時のメール保持、パスワードと
通知のクリア、送信中の操作制限、確認メール案内は従来どおり。

AccountSectionは従来のuseAuthを使い続ける。表示とログアウト処理をAccountPanelへ分離し、
実認証に接続しないテスト・プレビューにも使えるようにした。セッション監視やルーティング、
Supabase Client・パスワードの送信/保存方式は変更していない。
長いメールアドレスは折り返し、ログアウト中の無効化・失敗Noticeを維持する。

## 検証と比較資料

Jestでは保存・再読込・エラー・未保存確認・保存中の制限、非プリセット値の保持、
サーバー返却値の反映とAccountの状態保持、Auth切替・登録・通知・送信中の制限を確認する。
既存の翌日終了・DST・個別余白・Planner・認証の回帰テストも維持する。

Before/AfterはCodexのローカルvisualizations内の`step-9c-3/index.html`に保存する。
375/390/768/1440px、375/1440pxの200%文字、設定・時間選択・保存状態・認証・Accountを比較する。
Authのプレビューはモックのみで、実認証・確認メール送信は発生しない。
QA用ルートは成果物に含めない。200%は対象画面の文字と行高を拡大し、既知のタブバー問題は対象外。

iOS Simulator（375pt）の既存development buildで時間選択、保存、キーボード、保存失敗、
約214%のDynamic Type、モック新規登録と確認メール通知まで確認した。
実機での実認証、パスワード自動入力、VoiceOverの読み上げ順、Safe Area、最大文字サイズは
別途確認する。Web公開・実機への上書き・DB変更は行わない。

## Step 9C-4への引き継ぎ

- 200%文字のタブバーとナビゲーションの操作到達性。
- OSジェスチャーやブラウザ履歴を含む未保存変更の離脱方針。
- 実機のVoiceOver、Dynamic Type、キーボード・認証自動入力の最終確認。

Planner・保存データ・DB schema・依存ライブラリは変更していない。

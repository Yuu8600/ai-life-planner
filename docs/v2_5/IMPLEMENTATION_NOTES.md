# V2.5の実装と互換性

| 項目                   | 実装                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| 推薦ルール・画面・履歴 | src/features/recommendations/                                                                   |
| 今日・予定             | V25DailyRoutes、useV25Date、DayAgenda                                                           |
| タスクと目標           | 既存の TasksScreen、GoalsScreen とフォーム                                                      |
| 固定予定               | 既存の v2_events に対する専用リポジトリ。通常画面からの日次計画生成を分離                       |

## DB変更

1. 20261118100000_v25_recommendations.sql は tasks.estimated_minutes を nullable にする。既存の正値制約と保存済みの見積もりは維持する。action_steps と recommendation_results を追加する。後者は結果を参照対象・暦日ごとに一意にし、対象の削除後も記録時の名称で履歴を読める。
2. 結果の書き込みは record_recommendation_result に限定する。認証ユーザー、所有者、プロフィールの暦日を検証し、同じ対象・日付には最初に確定した結果を返す。単発タスクまたは一度きりの小さな行動の状態を同じトランザクションで更新する。小さな行動の親は複合外部キーとRLSで所有者を一致させる。
3. 20261118110000_v25_ai_action_drafts.sql は v2_approve_draft を拡張する。承認対象とリビジョンに加え、親タスク・紐付け先の目標の所有者と更新時刻を検証する。見積もりが未設定の既存タスクも下書きから更新できる。
4. DB型は分離したローカルSupabaseの実スキーマから、リポジトリで固定のCLIを使って生成した。

## 旧クライアントとデータ

既存のGoal、Task、計画、作業枠、活動履歴、AI会話・下書きの移し替えや削除はない。現行ソースに含まれるV1・V2 Plannerは時間未設定のタスクを新規配置の対象から外す。V2は保存済みの枠や履歴を表示できる。

**配布済みの旧Nativeアプリは、見積もり未設定のタスクを含む一覧の読み込みに失敗する。** 旧版のTaskアダプターは数値を必須としている。同じDBを使う旧版とV2.5は、本番で見積もり未設定のタスクを初めて書き込む前に、利用クライアントの切り替え計画が必要。並行試用はDBとアプリのbundle IDを分ける。

## 試用版の範囲

- 認証とTask・履歴の読み書きにはSupabaseへの接続が必要。AIと端末カレンダーは任意。
- 推薦順位は90日分のV2.5履歴を参照し、通常の履歴シートは直近7日分を表示する。V1・V2 Plannerの履歴はそれぞれの画面から閲覧する。
- 時間と余裕はアカウントごとに端末内へ保存する。「別の候補」は画面の表示中に保持する。
- 「予定」は一覧表示。時刻付きアプリ内予定の追加・削除、端末予定の閲覧に対応する。縦型時間軸と生活予定は高度なPlannerで扱う。

# ポートフォリオ用の開発紹介

## 30秒で説明する

目標を決めても、カレンダーの予定を見ながら「いつやるか」まで決めるのは手間がかかります。AI Life Plannerは、目標に紐づくタスクを予定の合間に割り振り、確認してから保存できるアプリです。「今日」の時間軸から完了やスキップを記録し、残り時間の計画を組み直せます。ログイン不要のWeb Demoではサンプルの一日を体験できます。

## 面接で説明できる設計判断

| 課題                                           | 実装と判断                                                                                                                                                                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| カレンダー上の隙間がそのまま使えるとは限らない | 端末カレンダーは権限を得て読み取り専用で取得。塞がる区間の統合、共通・個別の余白、最小空き時間を反映して候補を求める。活動が翌日にまたがる場合は計画日と暦日を分け、時刻表示はプロフィールのタイムゾーン、経過時間の計算はUTCを基準にする。 |
| 配置結果を確認してから使いたい                 | ルールベースで期限・優先度・所要時間を使って決定的に配置。承認時に最新データで再検証し、枠外や候補消失などで無効になった提案の保存を拒否。時間の境界や変更後の承認をJestで検証する。                                                        |
| 保存・再計画で記録を壊したくない               | Supabase AuthとRLSで操作をユーザー別に制限し、計画と明細をRPC内で一括保存。再計画では競合条件も確認する。完了は関連タスクも完了にし、スキップはタスクを残す。履歴は実行時点の内容を保持するので、計画を組み直しても参照できる。             |
| 閲覧者が設定なしで試せるようにする             | React NativeとWebで空き時間計算・計画・検証を共有。Webだけ端末カレンダーとSupabaseの代わりにサンプル・メモリ内Repositoryを使う。Web Demoではルールベースのみを使用し、任意のOpenAI連携はNativeからEdge Functionを経由する。                 |

実装の入口とRepositoryの役割は[アーキテクチャ](architecture.md)、日付や承認の境界は[翌日深夜対応の設計](overnight-planning.md)にまとめています。

## 開発と検証の進め方

要件を段階に分け、目標・タスク・予定から計画を作る流れと、承認・実行・履歴を先に整えました。その後、翌日深夜の活動、時間軸、画面ごとの情報の優先順位を順に改善しました。UIでは複数案を比較してClearを採用し、Web Demoの入口では初めての人がタスクを登録せずに試せる導線を優先しました。[要件定義](requirements/requirements-v0.1.md) · [Clearデザインシステム](clear-design-system.md)

Codexを、コードやテストの実装、既存実装の調査、ブラウザでの動作確認、差分確認の補助に使いました。開発の説明では、採用した要件・設計判断と、テストやブラウザ・実機で確認した範囲を区別します。PRとmainではGitHub Actionsで型・lint・フォーマット・Jestを実行し、Webの公開用成果物は静的exportと検査で確認します。[開発手順](development.md) · [Webの検証記録](web-demo.md#今回の公開準備で確認した範囲)

## 実機とブラウザでの確認範囲

- **Core v1のiPhone 16**では、端末予定の読み取り、計画の保存・実行・再計画などを確認。当時のPersonal Team署名のRelease版はUSBとMetroを外した状態での起動も確認しました。[実機の検証](ios-device-core-v1-verification.md) · [Releaseの検証](ios-personal-release.md)
- **Step 10のiPhone 16（PR #15相当）**では、Release版の上書き、セッション復元、設定の保存・復元、既存権限でのカレンダー表示を確認しました。QAデータによる追試で、古いプレビューの承認拒否、再生成・保存、完了・スキップ、再計画後の履歴保持を確認しました。USB解除後の起動・通信、実機VoiceOver・文字拡大、戻るジェスチャー、深夜の実時間表示、異常系などは未確認です。
- **iOS SimulatorとWeb**では、重複・短時間予定と文字拡大を確認した記録があります。最新のWeb DemoはローカルChromeでサンプルの生成から実行・再計画まで確認しました。撮影画像はWeb Demoです。[時間軸の記録](today-time-axis.md) · [ナビゲーションの記録](clear-navigation-layout.md) · [撮影画像](screenshots/README.md)

OpenAI実API、Android、Safariを含む全ブラウザの動作は、この公開準備で検証していません。

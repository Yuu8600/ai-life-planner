# V2.7 UI/UXの10原則

| 原則           | 実際の変更                                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 直感性         | Todayで時間内の候補と期限付きの例外を分ける。見積もり未設定は明記する                                                                     |
| 一貫性         | Today、タスク、小さな行動に同じチェック部品を使う。繰り返しは「今日の実施」、時間割は「作業枠」と表示する                                 |
| シンプルさ     | Todayの主要候補を先に表示し、所要時間を確認したい通常候補は必要時に開く。推薦方針の詳細は既存の一箇所に置く                               |
| 効率性         | AI案の編集から承認までを同じ画面にまとめた。予定の日付を直接選び、時刻は既存の選択部品で設定できる                                        |
| 状態の可視化   | 次の予定までの間隔と情報の出所、完了・見送りの対象名、予定共有の件数、承認する値を表示する                                                |
| 誤操作防止     | 端末読取と外部共有は別に確認する。承認内容を最終表示し、時間割の初回保存は明示操作にした                                                  |
| 操作の自由度   | 完了・見送りの後から実行履歴で戻せる。タスク一覧は直前の操作も取り消せる。AI確認から入力を保ったまま選択に戻れる                          |
| 認知負荷の軽減 | 予定行では「端末カレンダー」「アプリ内の予定」を表示する。通常設定と「時間割専用の設定」を区別した                                        |
| エラー対応     | 予定の片方の取得に失敗しても、確認できた予定とTaskを使う。承認失敗時は編集値の保持と再試行を行う                                          |
| モバイル最適化 | 日時選択とチェックに既存のタップ領域を使う。読み上げ名で一度きりの完了と当日実施を区別する。大型文字とVoiceOverでの確認手順をQAに記載した |

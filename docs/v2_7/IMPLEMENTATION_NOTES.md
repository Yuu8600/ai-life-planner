# V2.7 日常の推薦・AI相談・予定

基点は V2.6 の `3458a64`。作業ブランチは `feat/v2-7-ux-integration`。調査時の報告、仕様原本、別のQAメモは作業ツリーに保管した。

## 初版 Phase 1 — 今日と予定

- `DayAgenda` は端末とアプリ内固定予定を独立に取得する。取得できた側を使って時間判定を続け、片方だけ確認できたときはその範囲を表示する。端末の終日予定は「予定あり」として時間を占める指定がある場合に、プロフィールの暦日に変換する。同時刻の重複、重なり、日をまたいで進行中の予定は区間として扱う。
- `TodayRecommendationsScreen` は既存 `recommend` の候補と順位を再利用する。選んだ分数と確認できた予定間隔に収まる候補、今日・明日が期限の例外、時間を確認したい通常候補の順に表示する。同じ親タスクの候補は一件まで。通常候補の確認欄は、すぐ取り組める候補があれば初期状態で畳む。初期上限、期限優先、小さな行動、適用中の方針は従来の処理を使う。
- 判定はプロフィールの「今日」に重なる予定を対象にする。終日予定の時刻や端末側の取得範囲はOSのカレンダー実装にも依存する。推定所要時間と予定の間隔は参考情報。予定が見つからないときは空き時間の長さを推定しない。

## Phase 2 — 予定共有の相談から承認

- 端末予定の読取許可と、送信前の「参照情報」での選択は別。既定は共有なし。予定の有無、または選んだ予定の名前と開始・終了を送る。選択した日時はプロフィールの時間帯で確認でき、場所は別に選ぶ。端末ID、参加者、メモは送信項目に含めない。
- 予定を共有した回の相談文と回答、承認前の推薦方針は一時表示。会話を切り替えるかアプリを終了すると一時表示は失われる。新規相談では汎用名の会話枠が作られる。通信失敗時は、入力と共有設定を画面に保持する。共有対象は現在の端末カレンダーのみ。アプリ内の固定予定はTodayの時間判定に使う。
- `v27_reserve_calendar_ai` はV2.6の予算予約を再利用し、本人の一時相談の会話IDを記録する。返信・カレンダー・モデル提案はDB書き込みに渡さず、使用量と成功結果を記録する。モデルには `store: false` を指定する。外部サービス側のデータ保持はアプリ内履歴と別。
- 共有ありの回から保存できる提案は推薦方針に限定。自由記述の項目が必要なTask作成・Task編集・小さな行動は従来の共有なしの相談で利用できる。初期の同意画面と承認確認に保存対象を表示する。共有した相談文や回答を共有なしの会話に自動転記する機能は設けない。
- `v27_approve_calendar_policies` は認証ユーザー、会話、成功した共有リクエスト、対象の所有・状態を検証する。入力を方針の種類・Taskまたは目標のID・日付に限定し、固定の見出しと項目キーで選択分だけを保存。予定名をコピーしたモデル出力も永続保存の対象にならない。同じリクエストへの承認の再送は適用済みの処理として扱う。
- 通常の下書きは編集・項目選択・最終確認・承認を一枚で実施する。`v27_approve_edited_draft` はV2.6の版管理・選択承認を同一トランザクションで実行する。途中で失敗すると版の更新も取り消される。既存Taskの取り消し、方針の解除・再適用、旧下書きの履歴は以前と同じRPCを使う。

## Phase 3 — 日常操作と時間割

- タスク一覧のチェック直後は、対象名を表示してその場で取り消せる。以前の「完了済み」から戻す方法も使える。今日・タスク・小さな行動で、一度きりは「完了」、繰り返しは「今日の実施」を表示する。実施記録と本体の保存は従来のRPCを使う。取り消せない削除は確認に明記する。
- 予定画面は表示日を押して日付を選ぶ。アプリ内予定では開始時刻、終了時刻、翌日終了を選択できる。予定行で出所を確認できる。
- 時間割は設定内にある。初回は画面を開くと既存データを読み、利用者が「時間割の案を見る」から保存を確定した時点で作成する。V1履歴、既存時間割の再計画・変更・作業枠の記録を維持する。通常設定の時間帯と「時間割専用の設定」を区別する。
- 余裕選択、Taskの3フィルター、削除後の復元、AIによるGoalや予定の操作は今回の操作要件に含めなかった。Goal本体の画面、認証、優先順位の比較、旧Web Demoの入口は既存の利用フローを再利用した。Web Demoでは端末カレンダー・認証・AIの通信は提供していない。

## DB互換性

`20261122100000_v27_calendar_policy_approval.sql` は、AI予算記録にNULL許容の会話IDを追加し、新しいRPCを定義する。従来のRPCとテーブル、V1・V2の計画と履歴は引き続き利用する。既存行の書き換えは不要。旧V2.6アプリからの共有相談は従来の一時回答として処理する。V2.7は分離QAの 56821（DB 56822）を使用した。将来配備する際は互換マイグレーション、Edge Function、Nativeクライアントの順に確認する。

## 検証結果

- TypeScript、Expo lint、変更ファイルのPrettier、Gitの空白差分チェックに合格。Jestは78スイート・758件に合格した。
- 分離SupabaseでSQL 5本を実行した。共有相談の未保存、自由記述を含む承認の拒否、他人の対象と古い版の拒否、二重承認の防止、編集の取り消し、日別記録と既存V2計画の互換を確認した。APIでログインとAI未設定の応答、見積もりあり・未設定のTask作成と再取得、単発・繰り返しの完了と見送りの冪等性・復元を確認した。
- iOS Simulator Releaseビルドを署名し、別のアプリIDでインストールした。ログイン画面と、専用QAユーザーのセッションでTodayを表示した。短時間候補と期限付き例外、進行中のアプリ内予定による再分類を確認した。Simulatorでの画面タップ、端末カレンダー実データでの組み合わせ、実OpenAI応答、VoiceOverは手動QAの対象。
- Web Demoを一時ディレクトリに静的出力し、主要ルート、日本語HTML、アセット参照、Native・AI連携の非混入を検証した。

## 手動QAを受けた改善

- 今日の時間枠は30分・1時間・2時間・指定なし。未保存と廃止した15分設定は指定なしになり、既存の30分・60分は引き継ぐ。指定なしは利用者の時間上限を外す。既存の予定間隔・期限・重要度・目標・方針で推薦を続ける。
- 「あとで」は今日の日別結果に保存し、従来の `skipped` を読み書きする。翌日は通常の判定。Task・小さな行動は表示された行動単位で記録する。個別の「戻す」と一括の「すべて戻す」は、一覧の表示操作と分けた。
- 「これまでの記録」の複数選択は今日分が対象。過去分は閲覧できる。完了済みタスクの削除は本体が完了したものだけを対象にし、繰り返しの今日の実施とは分ける。関連する小さな行動とTask向けの方針は既存の連動削除に従い、記録のスナップショットや時間割は保持される。
- 追加マイグレーション `20261123100000_v27_batch_task_actions.sql` には一括の取り消しと完了済みTask削除の2つのRPCがある。一括で全件成功するか元に戻る。単独操作や旧画面のDB契約は従来どおり。
- アプリ内予定は既存の `v2_events` に保存し、時刻が重なる固定予定を引き続き推薦に反映する。通常の予定画面ではカレンダー一覧を先に置き、アプリ内予定の追加は一覧の下で利用できる。カレンダーにない状況はTodayの時間選択で一時的に反映できるため、多忙度の別設定や新しい予定管理機能は追加していない。
- 56821の `v2-chat` は起動済み。QAランタイムにはOpenAIキー、モデル、単価が未設定だったため、状態確認で `configured: false` を返した。Git管理外のQA用設定ファイルを作成し、アプリにサーバー設定の再確認を追加した。実OpenAI通信は手動QAの対象。

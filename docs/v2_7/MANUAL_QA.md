# V2.7 手動QA

Simulatorアプリ「AI Life Planner QA」と共通ローカルSupabase（API `127.0.0.1:56821`、DB `56822`）を使う。ブラウザのWeb Demoは旧デモ用のサンプル体験。端末予定、認証、AI相談を確認するにはNative版を開く。

| -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 「参照情報」で翌日・「選んだ予定の詳細」を指定。1件を選び、場所をオフで確認し「次の送信に使う」          | 選択した予定だけが内容表示の対象になる。共有設定を確定した段階では送信されない。入力欄では次の送信で共有する件数がわかる |

## 設定と高度な時間割

1. 設定から「時間割を開く」。保存済みの時間割がない未来日を選ぶ。閲覧と、「時間割の案を見る」→閉じるだけでは保存済みにならない。
2. もう一度案を開いて「この変更を保存」。同じ日を再表示すると保存した時間割が表示される。「作業枠を完了」の結果は枠に記録され、通常のTask完了とは別。
3. 過去の日付で既存の時間割とV1の記録を確認。「時間割専用の設定」で時間割用の活動時間と余白を確認し、通常の地域・時間帯が先に見えることを確認する。
4. 小さな表示領域・大きな文字・VoiceOverで、チェック、行の編集、送信同意、承認のボタンが区別できるか確認する。

## 回答直下の操作カード

- AIに「読書を追加して」と相談する。回答は提案として表示され、タスクは承認前に作られない。
- 回答直下のカードで内容を確認し「追加」を押す。保存後に「保存しました」へ縮まり、タスクタブへ移ると追加したTaskが表示される。
- 別の提案を「提案を却下」で取り消す。タスクは作られず、再起動後も取り消し表示になる。
- 追加を連打しても保存は一度だけ。通信失敗時は成功表示にならず、カードから再試行できる。
- Task編集、小さな行動、推薦方針も同じカードで確認する。編集後の適用と競合エラー、編集取り消しを確認する。
- 複数の相談と提案を作り、それぞれの回答直下に表示されることを確認する。以前のメッセージを読み込むと古い提案も対応する回答へ移る。表示範囲より古い提案は会話の先頭に保持される。
- キーボードを開いた状態でカードを編集・スクロールし、相談入力と送信に戻れることを確認する。
- カレンダー共有の回答・提案は画面内だけに表示される。会話を閉じて再表示しても共有した相談文・回答・予定の詳細が履歴に残らない。

作成日時による回答と提案の対応づけを使用する。旧データで日時がない場合も、会話先頭に提案を保持する。DBの承認RPC、競合チェック、二重適用防止は既存のものを使用する。

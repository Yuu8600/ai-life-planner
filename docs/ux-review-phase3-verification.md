## R-16：履歴表示・高度な予定入力

- 過去の計画・実行履歴の入口を維持し、両取得が成功して空のときだけ「ありません」と表示。
  読込失敗は再試行を表示し、計画なし・実行履歴ありのケースも保持する。
- 固定・生活予定の開始・終了を共通時刻ピッカー化。当日／翌日と生活予定の配置時間帯・所要時間を維持。
  保存先・旧RPC・移動時間の契約は変更しない。
- 全型チェック・ESLint・Prettier・91 suites / 841 tests・Web出力／分離検証成功。
  初回は既存Phase 2テストのRAFがJest終了後に発火して失敗。テストのタイマー後処理を追加して再実行成功。
- 現在コードのQAビルド成功。iPhone 17e / iOS 27.2で高度な予定の終了時刻・当日翌日選択・キャンセル、
  旧履歴入口と空表示を確認。入れ子の標準スクロールが動かず画面端スワイプで補完した。
  読込失敗・履歴のみ・生活予定保存は自動テストで確認。DBの実データ変更なし。
- セルフレビュー：履歴取得エラーを空と扱わず、保存済み時刻と既存の未保存ガードを維持。

## R-18：テーマ基盤・共通UI

- 全semantic roleを備えるdark palette、明示テーマとOS追従のopt-inをThemeProviderに追加。
  このPR段階では既定ライト・app.jsonのlight指定を維持し、一般画面のダーク表示は有効化しない。
- 共通ヘッダー・スクロール背景・状態表示・時刻選択の静的色をContextから解決。
  互換role用hookを提供し、旧画面の既存roleを保持。入力・通知・日付ピッカーもテーマ色を使用。
- 型チェック・ESLint・全Prettier・94 suites / 846 tests・Web出力／分離検証成功。
  全role一致、明示darkとlightの切替で共通ヘッダー・入力色が更新されることをテスト。
- 最終コードのQAビルド成功。iPhone 17e / iOS 27.2で予定・追加モーダルのライト表示を画像で確認。
  ダークのSimulator表示は全画面移行後の検証とし、この段階では自動テストのみ。DB変更なし。

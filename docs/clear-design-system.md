# Clearデザインシステム（Step 9B）

Step 9Aの比較案から、ユーザー採用のB案「Clear」を基準とする。情報の整列、読みやすさ、
操作の明確さを優先する。今回はテーマと共通部品の基盤であり、画面構成の全面変更はStep 9Cで扱う。

## トークン

`src/shared/theme/palette.ts`にライト用のセマンティック色、`tokens.ts`に寸法・文字を定義する。

| 用途                                     | 基準                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| 主色 / 押下色 / 淡い背景                 | `#3656A6` / `#294487` / `#EBEFFA`                                                  |
| ページ / Surface                         | `#F5F7FA` / `#FFFFFF`                                                              |
| 本文 / 補助情報                          | `#172235` / `#526176`                                                              |
| 装飾境界 / 入力境界 / フォーカス         | `#D7DEE8` / `#7B8798` / `#3656A6`                                                  |
| 成功・配置可能 / 警告 / エラー・現在時刻 | `#276749` / `#825A11` / `#B42318`                                                  |
| Calendar予定 / Planned Action            | グレー `#52606F` / ブルー `#3656A6`                                                |
| 文字                                     | 画面見出し28/36、セクション18/26、ダイアログ22/30、本文16/24、補助14/21、注記13/20 |
| 余白                                     | 4 / 8 / 12 / 16 / 24 / 32。ページの基本余白16                                      |
| 角丸                                     | 入力8、ボタン10、カード12、ダイアログ16                                            |
| 操作領域                                 | 原則44以上。標準ボタン48、入力50、設定行56の最小高。固定高で文字を切らない         |

寸法はReact Nativeの論理単位（Webではpx）。文字はOS/ブラウザの拡大を妨げない。
本文・状態色は通常文字4.5:1以上、入力境界・フォーカス等はSurfaceに対して3:1以上をテストする。
淡いカード境界は装飾用で、入力可能な境界とは区別する。
色だけに依存せずCalendar/Action・状態ラベル、選択チェック、アクセシビリティ状態を併用する。

`useTheme()` / `ThemeProvider`は新しい共通部品で利用できる。出荷するテーマはライトのみ。
従来の`colors.accent`等の別名は互換用に残す。既存画面の静的参照はライトに固定されるため、
将来のダークモード導入にはそれらの移行・全画面検証も必要。Providerを切り替えるだけでは完了しない。

## 共通部品

- `ActionButton`: primary / secondary / ghost / destructive。disabledとloadingを分け、
  loading時はspinnerとbusy状態を出し、再操作を防ぐ。ラベルは呼び出し側で指定する。
  押下色・Webのフォーカス輪郭・ラベル折り返しに対応。
- `FormField` / `FormInput`: ラベル・補助・エラー、入力境界・focus・disabledを統一。
  既存の明示的なaccessibilityLabelを尊重する。直接のFormInputにはラベル・エラーのヒントを関連付ける。
  入力値の変換・検証・保存は各機能に残す。
- `OptionGroup`: Goals/Tasksの重複した選択群を共通化。radioの選択・無効状態と44以上の領域を持つ。
- `Badge`: info/accent、neutral、success、warning、error。完了を主色から独立したsuccessへ移行。
- `Notice`: 情報・成功・警告・エラー。エラー文はalertとして読み上げ、回復操作を子として渡せる。
- `Card`: Surface・装飾境界・余白16・角丸12。状態パネルで利用する。
- `ModalHeader` / `ModalFrame`: Goals/Tasksの見出し・閉じる・余白・保存操作を共通化。
  NativeのpageSheetを維持しSafe Area/KeyboardAvoidingViewを利用する。
  Webは768未満で下部シート、それ以上で中央・最大640。本文はスクロール、保存は下部に固定。
  説明文は本文内に置き、拡大時の入力領域を確保する。保存中の閉鎖を防ぐ。
- 時間選択パネルも同じ見出しを利用。Webは既存のpopover/bottom sheetの使い分けを維持。
  `useModalFocus.web.ts`でEscape・Tab循環・開始位置への復帰を共有し、値変更でfocusを奪わない。
  Nativeの設定行は大きな文字サイズで縦積みにし、選択肢のスクロール位置は実測する。

新規ライブラリ・DB変更はない。フォームの値・validation・Repository呼び出し、Planner生成/保存、
Calendar取得、時間軸の位置計算は変更しない。

## 意図した表示差分

全画面で主色がグリーンからブルー、本文系の基準が16、ページ余白が24から16、カード角丸が12になる。
完了バッジと配置可能領域はグリーン、Calendarはグレーを維持し、Todayの凡例を実際の色へ合わせる。
Goals/TasksのWebフォームは全画面からダイアログへ、閉じると保存は共通操作へ変わる。
タスクのフィルターには拡大文字での折り返しと44以上の操作領域だけを追加する。
画面の並び順・情報構造・ナビゲーション構成は変更しない。

## 検証とStep 9Cへの引き継ぎ

- 全Jest、typecheck、lint、format:check、diff確認、Pages export/verifyを行う。
- Webは375 / 390 / 768 / 1440pxでToday・フォーム・選択パネルを確認する。
  共通フォーム・選択パネルの文字200%相当では文字と行高を倍にし、フォーム保存・閉じる・スクロールと横はみ出しを確認する。
  キーボードのTab/Escape、キャンセル・focus復帰、時刻の非15分値と余白値も検証する。
- iOS Simulatorは375pt、通常とDynamic Type拡大で時刻選択・タスク入力/保存を確認する。
  実データへ接続しない一時的なDemoRepositoryの画面構成を用い、検証後はルートを完全に復元する。
- 実機でVoiceOverの読み上げ順、ソフトウェアキーボード、Safe Area、長文・最大文字サイズを確認する。
  本番の認証や実Calendarの読み取り、実機インストールは今回の検証対象外。

Step 9Cでは残る画面内の個別スタイルと直接色参照を段階的に移行し、冗長な説明や情報階層を整理する。
PCの密度・ナビゲーション再設計、Todayのカード密度/重なり表示、全画面の文字拡大最適化は別途扱う。Webの既存タブバーは全テキストを強制200%にする検証で
ラベルがはみ出す場合があり、ナビゲーションを含む全体対応はStep 9Cで確認・改善する。
共通部品を使うだけで各画面のアクセシビリティが完了するわけではない。
保存済みPlanのwindow、計画日、余白・blocking・Calendar権限による空き時間の意味を維持する。

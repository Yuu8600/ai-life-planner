# Calendar・Planner Clear UI（Step 9C-4）

## Calendar

日付ナビゲーション → 選択日の予定 → 配置可能な空き時間 → 読み取り専用の案内の順に整理。
最大幅880px、本文16、Card・Badgeを使い、iPhoneは時刻と詳細を縦積みにする。
PCは時刻列と詳細を整列し、Nativeで大きな文字の場合は縦積みに戻す。
長い予定名・Calendar名・場所は切り詰めず、終日・availability・キャンセル済み・個別余白を文字で区別する。
既存の日付ナビゲーション・プロフィールtimezone・注入時計を維持する。

空き時間は枠数・合計分数・活動時間（翌日を含む）・各区間を示す。
Calendarの表示は、予定・余白・最小空き時間を適用した候補であり、保存済みActionや過去を
差し引くTodayの未配置時間とは異なる。計算・取得・権限処理は変更していない。
権限拒否、取得エラー、読み込み中は従来どおり空き時間を確定表示しない。

個別余白は共通ModalFrameへ移行した。適用中の設定と編集中の選択を区別し、共通値を常設する。
プリセット＋その他、0分上書き、保存・解除のRepository呼び出しを維持し、選択だけでは保存しない。
端末予定は編集せず、保存済みPlanへの反映には明示的な再計画が必要であることを案内する。
保存中は閉じる・キャンセル・選択・再保存を防ぎ、失敗はNoticeで表示する。

## Planner

生成前は「生成方法 → 作成 → 確認 → 保存」を案内する。生成後は概要・Action件数・予定を優先し、
生成方法の変更をプレビュー下へ移す。利用可能性やProvider選択の契約・判定は維持する。
Actionはブルー、Calendarはグレー、未配置の理由は本文、注意事項はWarning Noticeで表示する。
未配置タスクと警告は常時展開し、重要情報を隠さない。

未保存のプレビューはスクロール外の保存エリアを持ち、生成だけではTodayへ反映されないことを示す。
Safe Areaを含む既存AppScreenのfooterを使う。再生成・キャンセルは予定一覧の直後、未配置タスクより前。
再計画モードは見出しと保存ラベルで明示する。確認ダイアログ・競合防止・承認時の再検証は従来どおり。

生成完了時は本文先頭へ戻す。保存成功・stale・保存失敗はプレビュー直前へ表示し、状態変更時にも本文先頭へ戻す。
staleはWarning、保存・確認の通信失敗はErrorとして区別する。staleでは保存ボタンを出さず、
整合性が失われて保存できないこと・再生成が必要なこと・検証理由を示す。
通信失敗では内容を保持した再試行、保存成功ではTodayへの導線を維持する。
`usePlannerPreview`、生成・Validator・保存・再計画・DBは変更していない。

## Webの重なったパネル

個別余白モーダルから時間選択パネルを開くため、共通`useModalFocus.web.ts`を最前面の層だけが
Tab/Escapeを扱う構成へ変更した。EscapeはReact Native Webと同じkeyupで一度だけ処理する。
パネルの解除ごとに元の操作へフォーカスを戻し、最終モーダル終了後にbodyのスクロール制限を戻す。
値変更・保存中の再描画ではフォーカスを移さない。Nativeのモーダル処理は変更していない。

既存Calendar・Planner・余白・翌日/DST・Todayの回帰テストを維持し、長文、空き時間の意味、
個別0分・保存失敗・処理中の制限、プレビュー件数・未配置理由・警告、固定保存のUIテストを追加する。

日付移動・余白保存/解除・Provider選択・stale保存禁止・再試行を確認する。
OpenAIの視覚比較はローカルのProviderモックで、外部APIを呼び出さない。

Before/AfterはCodexのローカルvisualizationsの`step-9c-4/index.html`に保存する。
権限拒否・取得エラー・終日/重複予定・余白パネル・生成前/後・未配置・警告・保存状態・stale・再計画を比較できる。
検証用ルート・メモリRepositoryのfixtureはcommitや正式exportに含めない。

実機では実Calendar・認証付き保存、VoiceOver、Dynamic Type、Safe Area、重ねた時間選択、
長い予定と保存操作への到達を確認する。Web本番公開・実機更新・remote DB操作は行わない。
Step 9C-5へはナビゲーションの200%表示、OS/ブラウザ離脱と未保存確認の共通方針を引き継ぐ。

### Simulatorの文字サイズ切替に関する制約

約214%の設定で起動した場合は見出し・日付・一覧・保存操作を確認する。
一方、実行中にOSの文字サイズを変更すると、変更前から表示中のTextの高さが追随せず欠ける現象を
Simulatorで確認した（未変更の共通部品・日付ナビゲーターを含む）。再起動後は再計測される。
実機での再現性と共通Textの再計測方針はStep 9C-5へ引き継ぎ、実行中の切替まで検証済みとは扱わない。

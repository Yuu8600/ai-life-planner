# Todayの時間軸（Step 8）

Todayは1時間ごとの目盛りと、Calendar予定・Actionの縦型時間軸を表示する。
Calendarはグレー、Actionはブルー。時刻ラベルは現在のプロフィールtimezoneを使う。
保存済みPlanがあれば保存時のwindowを優先し、旧Planにwindowがない場合は保存timezoneの暦日から表示範囲のUTC instantを求める。
保存時のtimezoneが違っていても、保存instantを動かさず、ラベルだけ現在のプロフィールtimezoneで表示する。
未作成の場合は現在のPlanning Windowを使い、Calendar予定だけでも表示する。
設定変更だけでPlan・Actionを移動・再生成しない。

## 配置と操作

- `timeAxis.ts`の純粋関数で、UTC instantの経過分から座標と高さを計算する（1時間96px）。
  DSTの欠ける時間は作らず、繰り返す時刻はUTC offsetを併記する。翌日は「翌日 00:00」などと表示。
- 色帯の高さは実際の長さ。短時間でも44pt以上の操作領域を設け、文字拡大に合わせて領域を広げる。
  操作領域が重なるカードは別レーンへ置く。各レーンの幅を確保し、小画面では横スクロールする。
- 時間軸内は最大560ptの縦スクロール。「現在時刻へ」で赤い現在時刻線へ移動する。
  線は30秒ごととアプリ復帰時に更新し、表示期間外には出さない。Demoは注入されたサンプル時計を使う。
- 終日予定は時間軸上部へ分離する。
- カードや「次のActionを確認」から詳細パネルを開く。短い予定の全文、Task / Goal / 理由、
  実行状態、既存の完了・スキップ・更新中・エラーを確認できる。
- 読み上げ・キーボード操作と一覧での確認のため、下部に詳細・操作の一覧も残す。
  再計画、Activity Log、期限タスク、端末Calendarの読み取り専用方針は維持する。

## 空き時間の意味

破線の淡い緑の領域は、最新Settingsの活動時間・共通余白・個別余白・blocking判定・
最小空き時間を既存Free Time Calculatorで適用し、全保存済みActionの予約区間と過去を除いた時間。
現在時刻は次の分へ切り上げ、Actionを引いた後にも最小空き時間を判定する。
完了・スキップ済みActionも保存された予約区間を維持し、時間を空けるには明示的な再計画を使う。
Task固有の期限・長さ等によって、実際に配置できるTaskは異なる。

白い隙間を空き時間とは扱わない。権限なし、Calendar / Settings / 個別余白の取得失敗、
読み取り可能Calendarなし、読み込み中、計画日不一致では、配置可能時間を確定表示しない。
Calendar表示と空き時間取得は独立し、空き時間の失敗で保存済みActionの操作を止めない。

保存時と現在の活動時間が異なる場合は説明を表示する。
時間軸の範囲は保存時、空き時間は現在の設定を基準とし、時間軸の範囲に重なる部分だけ描画する。
隣接日取得・個別余白の適用は既存の`loadCalendarPlanningEvents`を利用する。
表示用と計算用の同一日付・intervalの取得を共有し、遅れて届いた古い日付の結果は破棄する。
Plannerの生成・保存ロジック、TodayRepositoryの保存データ取得、DB schema、依存ライブラリは変更しない。

## 確認手順

1. Plan未作成でもCalendar予定、終日領域、配置可能時間が表示されることを確認。
2. Planを保存し、時刻とカードの位置・長さ、次のAction、現在時刻線を確認。
3. 短いActionをタップし、全文・時刻・完了・スキップ・更新失敗を確認。
4. 重複予定を横スクロールし、すべてのカードを選択できることを確認。
5. 09:00〜翌日02:00を設定し、翌日01:00でも前日のPlanと連続した時間軸を表示することを確認。
6. Settings変更後も保存済みPlanが変わらず、空き時間のみ最新設定を使うことを確認。
7. 権限拒否・取得エラーで空き時間を確定表示せず、Action操作は利用できることを確認。
8. iPhone実機で縦・横スクロール、文字拡大、VoiceOver、Safe Area、復帰時の現在時刻更新を確認。
   WebではTab / Enterでカードを開き、Escapeで閉じ、フォーカスが戻ることを確認。

DB migration・Web公開・iPhone実機へのインストールはこの変更に含まない。

## Clear Today（Step 9C-1）

日付・見出し → 完了数/全Action数 → 次のAction → 時間軸 → 計算説明・Plan補足・再計画 →
期限タスク → 詳細操作一覧 → 実行履歴の順に整理した。重要な読み込みエラー・Calendar権限・保存windowの警告は維持する。
Plan未作成でもCalendarと配置可能時間を表示し、計画作成ボタンを上部へ置く。

次のActionは表示専用の純粋関数で選ぶ。予定時間内のscheduledを優先し、次に終了時刻を過ぎた未完了、
最後に未来のActionを開始instant/id順に選ぶ。現在時刻と終了が一致すれば予定時間外。
未完了を自動完了にせず、保存時刻・状態は変更しない。完了/skipは既存の詳細・Repositoryを利用する。
全件実行済み・0件の状態も明示する。詳細操作一覧は常時展開し、読み上げ・キーボードの代替経路を維持する。

DemoBannerは時計表示と「デモ操作」を常設し、時計変更/翌日01:00/リセットを展開する。
他画面でも同じ展開操作を使える。再読み込みで初期化する仕様は維持する。

ローカルWebで同じ08:00サンプル・900px高・スクロール前の時間軸コンテナ上端を測定:

数値はDemoBannerを含む。Nativeではバナーがないため別の位置となる。

生成/保存、完了/skip、翌日01:00、保存window維持はブラウザでも回帰確認した。
短時間・重複・DST/timezone・権限/空き時間は既存のテストを維持し、次のAction選択に4テストを追加した。
